# HaruVerse 관리자 콘솔

HaruVerse의 운영 작업을 위한 별도 SPA. 서비스 앱(`haruverse_react`)과 **완전히 분리된 앱**이다.

- **기술** — Vue 3 (Composition API) · Vite · TypeScript · Vue Router · Vuetify 3
- **주소** — `admin-haruverse.haru.company` (배포 예정)
- **접근** — `ADMIN` 권한 회원만

## 왜 별도 앱인가

서비스 앱은 React다. 관리자만 쓰는 화면을 그 안에 넣으면 일반 사용자가 받는 번들에
운영 코드가 섞이고, 라우팅도 복잡해진다. 무엇보다 **운영 도구는 서비스와 함께 죽거나
살면 안 된다** — 한쪽 배포가 다른 쪽을 건드리지 않도록 나눴다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5310
```

백엔드가 `localhost:8080`에 있어야 한다(`vite.config.ts`의 프록시 대상).
맥미니의 운영 백엔드에 붙여 보려면 터널을 연다.

```bash
ssh -f -N -L 8080:127.0.0.1:5301 macmini
```

## 구조

```
src/
  lib/auth.ts        토큰 보관 · JWT 페이로드에서 권한 읽기
  lib/api.ts         fetch 래퍼 — 토큰 첨부, 401 일괄 처리
  router/index.ts    라우팅 + 진입 가드
  plugins/vuetify.ts 테마 (서비스 앱 팔레트 + 관리자용 배경)
  layouts/           앱 바 · 사이드 메뉴
  views/             화면
```

## 알아둘 것

### API는 항상 같은 오리진으로 부른다

경로를 `"/api/..."` 로만 쓴다. 절대 URL을 쓰면 관리자 콘솔이 다른 서브도메인이므로
크로스 오리진이 되고, **백엔드에 없는 CORS 설정을 새로 만들어야 한다.**
개발에서는 Vite 프록시가, 운영에서는 컨테이너의 nginx가 이 경로를 백엔드로 넘겨
브라우저 입장에서는 언제나 same-origin이다.

### 라우터 가드는 '방어'가 아니다

가드는 JWT 페이로드를 **서명 검증 없이** 읽는다. `localStorage`를 고치면 통과할 수 있다.
그래도 문제가 없는 이유는, 통과한 화면이 부르는 모든 API가 백엔드에서
`hasRole("ADMIN")`으로 다시 검사되기 때문이다.
가드의 목적은 *권한 없는 사람에게 빈 화면 대신 안내를 보여주는 것*이다.

실제로 서명이 엉터리인 `role: ADMIN` 토큰을 넣어 확인했다 —
가드는 통과하지만 첫 API 호출에서 401이 돌아오고, 토큰이 지워지며 로그인 화면으로 되돌아온다.

### 로그인은 서비스 앱과 공유되지 않는다

`localStorage`는 오리진마다 별개다. 서비스 쪽에서 로그인해 두어도 관리자 쪽은 그 토큰을
볼 수 없다. 불편이 아니라 격리다 — 서비스 세션이 관리자 권한으로 새지 않는다.

### 권한은 토큰에서 읽는다

백엔드의 `LoginResponse`·`MemberResponse`에는 `role` 필드가 없다.
JWT의 `role` 클레임에는 있으므로 거기서 꺼낸다. 백엔드를 건드리지 않기 위한 선택이다.
