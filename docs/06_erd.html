1 ERD 다이어그램

erDiagram
    MEMBER   ||--o{ FAVORITE  : "registers"
    WORK     ||--o{ FAVORITE  : "listed-in"
    WORK     ||--o{ CHARACTER : "has"
    WORK     ||--o{ WORK_GENRE : ""
    GENRE    ||--o{ WORK_GENRE : ""
    STUDIO   ||--o{ WORK      : "produces"
    MEMBER { bigint id PK }
    WORK { bigint id PK }
    CHARACTER { bigint id PK }
    GENRE { bigint id PK }
    WORK_GENRE { bigint work_id FK }
    STUDIO { bigint id PK }
    FAVORITE { bigint id PK }

관계 요약: Work가 중심. Work–Character(1:N), Work–Genre(N:M via work_genre), Work–Studio(N:1), Member–Work(N:M via favorite).

2 핵심 테이블

work 작품 (애니/게임)

컬럼타입제약설명
idBIGINTPK, AUTO_INCREMENT작품 ID
titleVARCHAR(255)NOT NULL, INDEX제목
typeVARCHAR(20)NOT NULLANIME / GAME (enum)
synopsisTEXTNULL줄거리
release_dateDATENULL, INDEX출시·방영일
seasonVARCHAR(20)NULL, INDEX분기 (예: 2026-spring)
ratingDECIMAL(3,1)NULL평점
image_urlVARCHAR(500)NULL포스터
studio_idBIGINTFK → studio.id, NULL제작사
external_idVARCHAR(50)UNIQUE외부 API ID (중복수집 방지)
sourceVARCHAR(20)NOT NULLJIKAN / RAWG (출처)
created_at / updated_atDATETIMENOT NULLBaseTimeEntity

character 캐릭터

컬럼타입제약설명
idBIGINTPK캐릭터 ID
nameVARCHAR(255)NOT NULL, INDEX이름
image_urlVARCHAR(500)NULL이미지
work_idBIGINTFK → work.id, NOT NULL소속 작품

studio 제작사 · genre 장르

테이블.컬럼타입제약
studio.id / genre.idBIGINTPK
studio.name / genre.nameVARCHAR(100)NOT NULL, UNIQUE

work_genre 작품-장르 (N:M 조인)

컬럼타입제약
work_idBIGINTFK → work.id, PK(복합)
genre_idBIGINTFK → genre.id, PK(복합)

3 회원 · 즐겨찾기

member 회원

컬럼타입제약설명
idBIGINTPK회원 ID
login_idVARCHAR(50)UNIQUE, NOT NULL로그인 아이디
passwordVARCHAR(255)NOT NULLBCrypt 해시
nicknameVARCHAR(50)NOT NULL닉네임
roleVARCHAR(20)NOT NULLUSER / ADMIN
created_at / updated_atDATETIMENOT NULL가입·수정 시각

favorite 즐겨찾기 (Member ↔ Work)

컬럼타입제약설명
idBIGINTPKID
member_idBIGINTNOT NULL, INDEX회원 (※ MSA 대비 ID 참조)
work_idBIGINTNOT NULL, INDEX작품 (※ ID 참조)
created_atDATETIMENOT NULL찜한 시각
UNIQUE 제약
(member_id, work_id) 복합 UNIQUE → 같은 작품 중복 찜 방지.

4 인덱스 · 설계 노트

테이블인덱스목적
worktitle, release_date, season, type목록 필터·정렬
workUNIQUE(external_id)외부 API 중복 수집 방지(upsert)
favoriteUNIQUE(member_id, work_id)중복 찜 방지
memberUNIQUE(login_id)아이디 중복 방지
★ MSA 대비
favorite은 member·work를 JPA FK 연관이 아닌 ID(BIGINT) 참조로 둔다 (DB FK 제약은 선택). 추후 서비스 분리 시 조인 의존을 줄이기 위함. (단 work 내부의 character·work_genre는 FK 사용)

5 Elasticsearch 매핑 (검색 전용)

MariaDB의 work를 검색용으로 색인하는 WorkDocument (별도 모델).

필드ES 타입분석기
idkeyword-
titletextnori (한국어 형태소) + edge_ngram(자동완성)
characterNamestextnori (캐릭터명 통합 검색)
genreskeyword- (필터)
type · seasonkeyword- (필터)
rating · releaseDatefloat · date- (정렬)
동기화
외부 수집(external) 또는 work 변경 시 → WorkDocument 색인. MariaDB=원본 / ES=검색 역할 분리.
