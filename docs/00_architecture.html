1 전체 시스템 아키텍처

프론트엔드(SPA)와 백엔드(REST API)를 분리한 구조. 프론트는 화면을, 백엔드는 데이터·검색·인증을 담당하며 JSON + JWT로 통신한다.

2 인프라 & 배포 구성

개발은 윈도우 PC, 운영은 맥미니(셀프호스팅). 분리 구조라 nginx가 프론트 정적 파일 서빙 + /api 백엔드 프록시를 담당한다.

⚠️ 운영 유의
① 맥미니는 데모/면접 시 전원 ON 유지 ② Elasticsearch RAM 큼(16GB+ 권장) ③ 비밀번호·키는 .env 분리(평문 커밋 금지) ④ nginx·app·mariadb·es를 Docker Compose 한 파일로 관리
★ 포폴 강점
"프론트/백 분리 + nginx 리버스 프록시 + Docker Compose + 터널 외부공개"는 인프라·DevOps 역량을 함께 증명한다.

3 데이터 수집 파이프라인

크롤링이 아닌 외부 공개 API에서 스케줄러 배치로 수집 → MariaDB 적재 → Elasticsearch 색인.

flowchart LR
    SCH["스케줄러
(배치 · @Scheduled)"] -->|"주기 호출 (rate limit 고려)"| API["외부 API
Jikan / RAWG"]
    API -->|"작품·캐릭터·장르"| DB[("MariaDB 적재
중복/갱신 처리")]
    DB -->|"색인"| ES[("Elasticsearch")]

처리 포인트: API rate limit(지연·페이징), 데이터 정합성(external_id 기준 upsert), 실패 재시도.

4 주요 흐름 — 시퀀스

① 통합 검색

sequenceDiagram
    participant U as 사용자
    participant FE as Frontend SPA
    participant BE as Backend
    participant ES as Elasticsearch
    U->>FE: 검색어 입력 (자동완성)
    FE->>BE: GET /api/search?q=...
    BE->>ES: 검색 쿼리 (multi_match)
    ES-->>BE: 매칭 결과 (스코어순)
    BE-->>FE: JSON 응답
    FE-->>U: 결과 렌더

② 로그인 & 인증 (JWT)

sequenceDiagram
    participant U as 사용자
    participant FE as Frontend SPA
    participant BE as Backend
    U->>FE: 로그인 (id / pw)
    FE->>BE: POST /api/auth/login
    BE-->>FE: JWT 토큰 발급
    FE->>FE: 토큰 저장 (메모리/스토리지)
    Note over FE,BE: 이후 요청마다 Authorization: Bearer {token}
    FE->>BE: GET /api/favorites (+ 토큰)
    BE->>BE: 토큰 검증 (Security Filter)
    BE-->>FE: 인증 후 즐겨찾기 응답
